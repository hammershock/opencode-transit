# RFC-0022：Agent 可见的工具执行截止时间

## 动机

一次文件搜索曾因绝对 glob 模式与搜索根目录不匹配，在宽泛目录下运行约 50 分钟。Session 和子 Agent 在此期间仍在运行，但用户看到的结果像是任务意外停止。工具的模型可见参数、传输层空闲超时和实际执行期限目前各不相同：部分搜索没有超时，MCP 进度消息可以重置等待计时器，网页响应正文可能在响应头之后无限等待。

Agent 应在调用前知道工具的执行预算，能够在允许的范围内传入更长预算；运行时必须以同一个绝对截止时间停止执行。人工决策和后台 Session 的生命周期需要单独定义，不能被一个通用工具计时器误杀。

## 边界与术语

- **执行时间**从所有必要的人工授权完成、工具开始执行 I/O 或计算时起算，到工作完成或停止时结束。校验参数可在此之前快速失败。
- **人工等待**包括 permission 和 Question。等待用户回答不消耗执行时间；用户可以显式取消。
- **绝对截止时间**只在开始时计算一次。进度消息、响应分块、产生部分结果和内部重试均不刷新它。
- **清理宽限**是截止时间后终止进程、关闭连接和释放资源所需的有界时间。模型可见的完成时间可能包含清理宽限，但被执行的工作不得继续运行。
- **Session 生命周期**与工具执行不同。Task 的子 Session 可继续存在，尤其是后台 Task；工具调用结束不能擅自取消已移交所有权的后台工作。

## 拟定契约

1. 可能阻塞的前台工具默认执行预算为 120,000 ms。更短的服务特定预算可以保留，但必须在 Agent 可见的描述中说明。Agent 可见的 `timeout` 输入统一使用毫秒；Agent 可以在工具定义允许的范围内显式传入预算，实际运行使用解码后的同一数值，不能暗中加长。每个工具声明默认值和上限。现有 shell/search 的上限为 600,000 ms，WebFetch 为 120,000 ms。MCP 的服务器级覆盖值是连接配置，不是 MCP 服务器拥有的工具输入字段。
2. 执行器启动后创建单调的绝对截止时间，向进程、HTTP/MCP 请求或可取消的工作单元传递取消信号。底层空闲超时可以更短，但不能替代绝对截止时间。超时后返回可识别的失败，包含实际使用的预算，并记录非敏感的工具名、开始时间、预算与停止原因。
3. 模型可见的工具描述和参数必须反映有效预算。若预算来自配置，运行时在提供工具定义时展示该值。动态 MCP 工具不得在服务器的参数 schema 中注入可能冲突的 `timeout` 字段；未来逐次调用覆盖值应使用独立的调用 envelope。
4. 多层执行采用就近的最早截止时间。`execute` 脚本的总预算与其中每个 MCP 调用的预算分别计算；子调用只能使用总预算的剩余时间。显式允许的串行多调用不能使外层调用无限延长。
5. 前台 Task 需要单独的 Agent 可见等待预算与子 Session 取消/继续规则。后台 Task 返回后，其子 Session 不属于原工具调用的执行预算。人工授权、Question 和等待已有后台任务的操作不得继承默认两分钟执行计时器；各自需要明确的等待或取消契约。
6. 所有入口共享此契约，包括 V1/V2 内建工具、Location 工具、远端执行和插件/自定义工具。不能取消的同步/native 操作不得宣称有硬截止时间；应移入可终止的工作单元，或在迁移期间清晰标识为尚未覆盖。

## 已有修复与待覆盖路径

本 RFC 为 Draft，以下已合并 PR 修复了明确的 bug，但不代表全局契约已实现或通过验收：

- [#574](https://github.com/hammershock/opencode-transit/pull/574) 修正绝对 glob 的搜索根目录；[#576](https://github.com/hammershock/opencode-transit/pull/576) 在 ripgrep 入口拒绝错误的绝对过滤器。
- [#578](https://github.com/hammershock/opencode-transit/pull/578) 为 V1 Glob/Grep 提供默认两分钟、可显式指定的绝对搜索期限。
- [#580](https://github.com/hammershock/opencode-transit/pull/580) 限制 V1 shell 参数并移除额外的 100 ms 执行延长；V2 Bash 已有两分钟默认值。
- [#582](https://github.com/hammershock/opencode-transit/pull/582) 为 MCP 子调用加入默认两分钟绝对期限，并禁止进度重置。
- [#584](https://github.com/hammershock/opencode-transit/pull/584) 将 V1/V2 WebFetch 默认期限设为两分钟，并覆盖 V1 的完整响应正文。

仍需独立实现：V2 FileSystem 搜索的 ripgrep 与同步 FFF 后端、V1/V2 WebSearch 的模型可见预算与正文读取、Code Mode 整体预算、前台 Task 的等待/子 Session 规则，以及读写文件、插件和自定义工具的阻塞执行边界。FFF 同步函数运行于当前线程时，普通 Promise/Effect 计时器不能保证在到期时中断它；需要可终止的 worker 或等价边界。

## 兼容、权限与恢复

超时不是权限提升。显式更长预算仍使用原工具权限与 Location，不改变文件或网络作用域。超时前产生的外部副作用可能已提交；返回信息不能声称回滚。工具重试应按各工具原有幂等性契约执行，尤其是写入与远端操作。默认两分钟可能使旧的长调用提前失败；Agent 应看到已用预算和允许的重试上限，而不是自动无限重试。

本 RFC 不修改 RFC-0004 User Shell 的十分钟一次性执行上限，也不改变 V2 Session 的 prompt admission、runner 所有权或后台 Task 的存活规则。同步/远端/平台特定行为在对应实现任务中验收，不从 Mac 的单机测试推断 Windows、WSL2 或远端结果。

## 验收与拆分

1. 为每个工具入口列出执行、人工等待和后台生命周期阶段，Agent 可在调用前看见实际预算与上限。
2. 使用真实进程、流式 HTTP、持续 MCP 进度和同步/native 搜索验证到期后停止工作；同时测量清理宽限，并确认用户取消优先。
3. 检查 Code Mode 多个串行调用受到外层预算约束，较长的单个子调用遵循最早截止时间。
4. 检查 permission/Question 不因执行计时器到期而自动拒绝，后台 Task 已移交的子 Session 不因原工具返回而停止。
5. V1/V2、Mac 与受影响的 Windows/WSL2、远端路径按测试工作流选择验收；未覆盖的入口不得声称全局硬限制已交付。

实施应按执行边界拆分为独立 issue/PR：V2 搜索可终止性、Code Mode 总预算、Task 等待与所有权、通用工具执行器及插件边界。接受本 RFC 后再将其状态与实现链接更新为实际完成的范围。
